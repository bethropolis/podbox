# Contributing

Thanks for helping with podbox. This page covers setting up a checkout,
the checks a change has to pass, and how releases work. Coding agents should
also read [AGENTS.md](AGENTS.md), which lists the project's rules in more
detail.

## Setup

[mise](https://mise.jdx.dev) is the recommended way to get every tool at the
version CI uses:

```bash
mise install          # bun, just, hk, shellcheck, wasm-pack (from mise.toml)
hk install            # git hooks: clippy + version check on push
```

Rust comes from [rustup](https://rustup.rs), which reads `rust-toolchain.toml`
and installs the pinned toolchain with clippy and rustfmt on first use. Add
the musl target so the embedded guest is built static, as in releases:

```bash
rustup target add x86_64-unknown-linux-musl     # aarch64-unknown-linux-musl on arm64
rustup target add wasm32-unknown-unknown        # only for the Studio wasm build
```

Without the musl target the guest still builds, but dynamically linked, and
it may not run in images with a different libc.

You also need Podman 5.5 or newer and a systemd user session to try podbox for
real. The test suite needs neither.

## Project structure

```
crates/
  podbox/            host CLI (package podbox-cli): config, codegen, commands,
                     socket host, Quadlet/systemd install
  podbox-guest/      guest daemon and interceptors, embedded into the host binary
  podbox-protocol/   host↔guest wire format, shared by both sides
  podbox-wasm/       config and codegen for the website Studio
docs/                user documentation (also published on the website)
images/              base image Containerfiles
scripts/             install, version bump, wasm build, asset generators
website/             Astro site: landing page, docs, Studio
```

`docs/architecture.md` explains how the pieces fit together.

## Building

```bash
cargo build -p podbox-cli                 # debug host CLI, guest embedded
cargo build --release -p podbox-cli       # what users get
just guest                                # guest binary alone (musl)
```

`crates/podbox/build.rs` builds `podbox-guest` and embeds it with
`include_bytes!`; no separate step is needed.

## Checks

Run these before opening a PR. CI runs the same set.

```bash
just check                # clippy -D warnings + all tests
cargo fmt --check
hk check                  # fmt, shellcheck, whitespace, large files, private keys
cargo check -p podbox-cli --lib --no-default-features --target wasm32-unknown-unknown
```

The last line keeps the library building for the browser. Code that needs
the OS (processes, sockets, `nix`) belongs behind the `cli` feature.

Tests never need podman or systemd: external binaries are stubbed and state
lives in temp dirs. Snapshot tests use [insta](https://insta.rs); review
changes with `cargo insta review` rather than accepting them wholesale. A bug
fix should come with a test that fails without it.

## Website and Studio

```bash
cd website
bun install
bun run dev               # http://localhost:4321/podbox/
bun run typecheck
bun run check:studio      # every Studio preset must round-trip through the Rust engine
```

`check:studio` uses the wasm bindings in `website/src/wasm`, which are
committed. Rebuild them with `scripts/build-wasm.sh` after changing the config
schema or codegen.

## Docs

`docs/*.md` is the source of truth. `bun run build` in `website/` syncs it into
the site and regenerates the search index; don't edit
`website/src/content/docs/` directly. Diagrams and logo files in
`docs/assets/` are generated by `scripts/gen-diagrams.py` and
`scripts/gen-brand.py`, so edit the script and re-run it.

## Changing behaviour users depend on

- **Config keys.** A new key needs its Rust type and validation, codegen,
  `docs/config.md`, and the Studio (`website/src/design/islands/studio/`),
  plus a case in `website/scripts/check-studio-parity.ts`.
- **CLI output.** JSON output, error codes and exit codes are a contract for
  other tools ([docs/clients.md](docs/clients.md)). Add fields freely, but
  don't rename or remove them, and update the tables in `docs/cli.md` and
  `docs/clients.md` together with the code.
- **Protocol.** Users' images contain a baked-in guest, so the protocol must
  stay compatible with older guests. Additive messages are fine; a breaking
  change bumps `PROTOCOL_VERSION`.

## Pull requests

- One logical change per PR, with a short imperative title and the reasoning
  in the description.
- Include docs and Studio updates in the same PR as the behaviour they
  describe.
- podbox is MIT-licensed. Don't copy code from GPL projects (distrobox
  included). Ideas are fine, so re-implement from a description.
- Security issues: don't open a public issue. See [SECURITY.md](SECURITY.md).

## Versioning and releases

```bash
scripts/bump-version.sh <new-version>     # updates Cargo.toml, commits, tags
```

Tags follow `v<major>.<minor>.<patch>`. The pre-push hook warns when
`Cargo.toml` doesn't match the latest tag.

Pushing a tag runs `.github/workflows/release.yml` with GoReleaser:
1. Host binaries for x86_64 and aarch64, glibc and musl.
2. Container images (Fedora multi-arch, CachyOS, dev) on ghcr.io.
3. Archives with checksums, the `podbox-bin` AUR package and the Homebrew cask.

After a successful non-prerelease release, `publish-crates.yml` publishes
`podbox-protocol`, `podbox-cli` and `podbox-guest` to crates.io. The website
is built and deployed by `docs.yml`.
